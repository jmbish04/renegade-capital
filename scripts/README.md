# Trump Policy RAG Pipeline

This directory contains the Python pipeline used to ingest, analyze, and map the "America's AI Action Plan" policy document into the Renegade Capital infrastructure. 

The pipeline transforms raw PDFs into structured data, generates high-quality embeddings, and uses sequential AI agents to analyze the text, assign tags, and identify ideal podcast guests based on the policy content.

## Prerequisites

1. **Python Environment:** Requires Python 3.10+
2. **Dependencies:**
   ```bash
   pip install PyPDF2 markitdown requests openai openai-agents pydantic
   ```
3. **Environment Variables:**
   ```bash
   export WORKER_URL="https://renegade-capital.hacolby.workers.dev"
   export CLOUDFLARE_AI_GATEWAY_TOKEN="<your-cloudflare-api-token>"
   export CLOUDFLARE_ACCOUNT_ID="<your-account-id>"
   ```
   *(Note: The script will attempt to use the `tokens` CLI tool as a fallback if the Cloudflare secrets are not set in the environment).*

## Usage

To run the full pipeline:
```bash
python scripts/ragify_trump_policy.py
```

## Pipeline Architecture

The pipeline follows a deterministic, 9-step orchestration flow. It extracts text, converts it to Markdown, generates vector embeddings via Cloudflare Workers AI, and then runs a multi-agent analysis to generate structured insights.

```mermaid
flowchart TD
    Start([Start Pipeline]) --> ExtractPages[1. Extract Pages\nPyPDF2]
    ExtractPages --> ConvertMD[2. Convert to Markdown\nmarkitdown]
    ConvertMD --> ExtractPDFs[3. Extract Single-Page PDFs]
    ExtractPDFs --> UploadR2[Upload to R2\nvia Worker API]
    ConvertMD --> ChunkText[Chunk Text\nMax 450 tokens]
    ChunkText --> GenerateEmbeddings[4. Generate Embeddings\nBGE-large-en-v1.5]
    GenerateEmbeddings --> UpsertVectorize[5. Upsert to Vectorize\nvia Worker API]
    
    UpsertVectorize --> FetchData[6. Fetch Existing Guests\n& Research Data]
    FetchData --> AIAnalysis{7. AI Agent Analysis Flow\ngpt-oss-120b}
    
    subgraph Multi-Agent Flow [Deterministic Sequential Agents]
        PolicyAnalyzer[Policy Analyzer Agent\nExtracts structured analysis]
        TagMapper[Tag Mapper Agent\nAssigns taxonomy tags]
        GuestMatcher[Guest Matcher Agent\nFinds relevant podcast guests]
        
        PolicyAnalyzer --> TagMapper
        TagMapper --> GuestMatcher
    end
    
    AIAnalysis --> Multi-Agent Flow
    
    Multi-Agent Flow --> PersistD1[8. Persist to D1\nvia Worker API]
    PersistD1 --> UpdateGuests[9. Update Guest Rationale\nGenerate custom pitch]
    UpdateGuests --> End([End Pipeline])
```

## Step-by-Step Breakdown

1. **Extract Pages:** Reads the PDF using `PyPDF2` and extracts raw text page by page.
2. **Convert to Markdown:** Uses Microsoft's `markitdown` library to convert the raw text into clean, structured Markdown format.
3. **Extract Single-Page PDFs:** Splits the original PDF into individual pages and uploads them to Cloudflare R2 for later UI display.
4. **Generate Embeddings:** Chunks the Markdown text to fit within 512-token limits, then generates vector embeddings using the `@cf/baai/bge-large-en-v1.5` model via the Worker API.
5. **Upsert to Vectorize:** Pushes the generated embeddings into the Cloudflare Vectorize index for semantic search capabilities.
6. **Fetch Data:** Pulls down existing Guests and Research records from the D1 database to provide context for the AI agents.
7. **AI Agent Analysis:** Runs a sequential orchestration flow using the `openai-agents` SDK (pointed at Cloudflare's `gpt-oss-120b`):
   - **Policy Analyzer Agent:** Reads the page and outputs structured analysis, summaries, and organizing strategies.
   - **Tag Mapper Agent:** Maps the analysis to the predefined Renegade Capital taxonomy.
   - **Guest Matcher Agent:** Finds the best podcast guests to discuss the policy based on their expertise and background.
8. **Persist to D1:** Saves the structured JSON results, relationships, and metadata directly to the D1 database.
9. **Update Guest Rationale:** Generates a custom 3-4 sentence podcast pitch for matched guests, explaining exactly why they fit the episode context, and updates their D1 record.

## Data Structure

The pipeline is designed to work with the updated relational database architecture:
- Pages are decoupled from monolithic transcripts.
- Tags and Guests are mapped using relational junction tables (`trump_policy_page_tag_map` and `trump_policy_page_podcast_guest_map`).
- Transcripts and Episodes are now generated in a separate macro-level orchestration pass, using the tags and analysis generated by this pipeline.
